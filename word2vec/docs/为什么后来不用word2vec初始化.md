# 为什么后来不用 word2vec 先把词映射成向量?

问题: 为什么不先用 word2vec 把词映射成向量, 再让模型拿这些向量去做推理或具体任务 (比如翻译), 而是要重新训练 embedding 层?

其实早期大家就是这么做的。2014 到 2017 年左右, 用 word2vec 或 GloVe 先把词映射成向量、再交给下游模型, 是很常见的做法。后来不再这么做, 主要有以下几个原因。

## 1. word2vec 学到的"相似"不一定是任务需要的"相似"

word2vec 的目标是"出现在相似上下文里的词, 向量要接近"。但很多词上下文相似, 意思却相反:

```
the movie was good .
the movie was bad .
```

`good` 和 `bad` 的上下文几乎一样, 所以在 word2vec 里它们的向量**很接近**。对情感分类来说, 这正是最需要区分开的两个词。

翻译也有类似问题: word2vec 里 `big`、`large`、`huge` 挤在一起, 但翻译时模型需要知道 `grande` 该对应哪一个。任务真正需要的区分, word2vec 不一定学到了。

端到端训练的 embedding 由任务的 loss 直接驱动: 任务需要区分什么, 它就学会区分什么。

## 2. 同一个词在 word2vec 里只有一个向量

`bank` 在"河岸"和"银行"两个意思下是同一个向量。模型无论如何都要在后面的层里根据上下文把它区分开。

这意味着, **真正难的"理解"其实发生在 embedding 之后的层里**。word2vec 只替你做了最简单的第一步, 也就是把 id 换成一个向量, 后面的工作一点也没少。

## 3. embedding 层本身并不难学

embedding 是一张查找表, 训练它的代价几乎为零, 只要数据够多, 它就能从零学好。本仓库的 Seq2Seq (11.8 万句对) 第 1 个 epoch 结束时 BLEU 就到了 30, 说明随机初始化的 embedding 很快就学出了有用的东西。

预训练词向量能帮上忙的场景, 主要是**数据很少**的时候: 几千条标注数据不足以学好上万个词的向量, 这时借用 word2vec 的通用知识就有价值。

## 4. 词表和分词对不上

- word2vec 按整词切分, 词表是固定的, 没见过的词就没有向量 (OOV)。
- 现代模型用子词 (BPE、WordPiece), `playing` 会拆成 `play` 和 `##ing`, word2vec 里根本没有 `##ing` 这样的向量。
- 本仓库也是如此: text8 只有英文、没有标点、没有 `i'` 这类 token, 而 Seq2Seq 编码器的输入是法语。

## 5. 更好的做法: 预训练整个模型, 而不只是第一层

回头看, word2vec 本身就是一种**非常浅的预训练**: 只有一层 embedding, 任务是预测邻居词。

BERT 和 GPT 把这个思路推到了极致:

| | word2vec 初始化 | BERT / GPT 预训练 |
|---|---|---|
| 预训练了什么 | 只有第一层 (查找表) | 全部层 |
| 输出的向量 | 静态: 同一个词永远同一个向量 | 上下文相关: `bank` 在不同句子里向量不同 |
| 下游任务要从零学什么 | 除 embedding 外的所有层 | 基本只有最后一层输出头 |

既然可以预训练整个模型, 只预训练第一层就没什么意义了。embedding 层作为整个模型的一部分, 在预训练里一起学好就行。

## 总结

word2vec 的思路没有错, 只是**太浅**: 它只把"词是什么"这一步提前做了, 而且做得和具体任务不一定对齐。现在有两种选择:

- 数据足够时, 像本仓库的 Seq2Seq 那样端到端从零训练;
- 数据不够时, 直接拿整个预训练好的模型 (BERT、GPT) 来微调, 而不只是借一层词向量。

"先用 word2vec 做 embedding"卡在两者之间, 所以现在很少用了。
