# 负采样 (Negative Sampling)

> 对应代码: [model.py](../model.py) `_neg_sampling_loss`、[data.py](../data.py) `build_noise_table`、[train.py](../train.py) 训练循环。
> 论文: Mikolov et al., 2013, *Distributed Representations of Words and Phrases and their Compositionality*。

---

## 1. 什么是负采样

Word2Vec 原本的目标是：给定中心词 $c$，预测上下文词 $o$ 的概率，用的是全词表 softmax：

$$
P(o \mid c) = \frac{\exp(u_o^\top v_c)}{\sum_{w=1}^{|V|} \exp(u_w^\top v_c)}
$$

- $v_c$：输入侧向量 (`in_embed`)
- $u_w$：输出侧向量 (`out_embed`)

**负采样把"从 |V| 个词里选出正确的那个"这个多分类问题，换成了若干个二分类问题：**

- 真实出现在一起的 $(c, o)$ → **正样本**，标签 1
- 从一个噪声分布 $P_n(w)$ 里随便抽 $K$ 个词 $w_1..w_K$，和 $c$ 组成 $(c, w_k)$ → **负样本**，标签 0

对每个正样本，损失为：

$$
\mathcal{L} = \underbrace{-\log \sigma(u_o^\top v_c)}_{\text{1 个正样本的误差项}} \quad - \quad \underbrace{\sum_{k=1}^{K} \log \sigma(-u_{w_k}^\top v_c)}_{\text{K 个负样本的误差项}}, \quad w_k \sim P_n(w)
$$

直观理解：**把真实上下文的点积往大推，把随机词的点积往小推**。模型要学的只是"这对词是真搭配还是随机凑的"。

**损失有几项？** 恰好 **1 + K** 项：1 个正样本项 + K 个负样本项。K=5 时只有 6 项；全词表 softmax 则要对 |V|（比如 10 万）个词求和。一个 batch 有 B 个正样本对时，这一步 loss 一共包含 B × (1 + K) 项。

### 通俗例子：把"十万选一的填空题"换成"几道判断题"

假设你在教一个完全不懂中文的小孩（模型）学词语搭配，手上有一本 **10 万词**的字典和一句话："我喜欢**吃苹果**"。目标是让他知道"吃"和"苹果"常常一起出现。

**笨办法（全词表 softmax）= 填空题**

题目是"吃 ____"。小孩必须把字典里 10 万个词挨个试一遍打分："吃+石头"、"吃+天空"、"吃+跑步"……一共 99,999 个错词，还要保证"吃+苹果"的分数比它们都高。每学一句话都要翻遍整本字典，太慢了。

**聪明办法（负采样）= 判断题**

1. **正样本**：指着书告诉他，"吃+苹果"是真搭配，要打**高分**。
2. **负采样**：闭着眼随便翻字典抽 K 个词（比如 K=3，抽到"石头"、"美丽"、"打篮球"），告诉他：
   - "吃+石头"是假搭配，打**低分**
   - "吃+美丽"是假搭配，打**低分**
   - "吃+打篮球"是假搭配，打**低分**

这样只算 1 + 3 = 4 次，而不是 10 万次。只要一直给他看真实句子，同时不断随机抽几个词当反例，久而久之他就知道"吃"和食物有关、和"石头"无关，不需要每次都和整本字典比。

- **负 (Negative)**：随机拼凑出来的**假搭配**（"吃+石头"）
- **采样 (Sampling)**：不把所有错词都算一遍，每次只**随便抽几个**当反例

> 严格来说，负采样是 NCE (Noise Contrastive Estimation) 的简化版：NCE 能渐近地逼近真正的 softmax 概率，负采样丢掉了那个修正项，因此**它不再是一个合法的语言模型概率**——但我们只关心词向量质量，不在乎这一点。

## 2. 在训练流程中具体怎么做

以 Skip-gram 为例，本项目中一步训练的完整流程：

### Step 0：训练前构建噪声表 (只做一次)

```python
# data.py
p = counts ** 0.75          # 词频的 3/4 次方
p /= p.sum()
reps = round(p * 1e7)       # 每个词在表里重复的次数
table = repeat(arange(V), reps)   # 长度约 1e7 的大数组
```

一个词在表中出现的次数正比于 $\text{count}(w)^{0.75}$。之后采样 = 随机取下标，O(1)。

### Step 1：生成正样本

对语料做下采样、动态窗口，产出一批 `(center, context)` 对，形状都是 `(B,)`。

### Step 2：采负样本

```python
# train.py
neg = noise_table[torch.randint(len(noise_table), (B, K))]   # (B, K)
```

每个正样本配 K 个负样本。注意**负样本在每一步都重新采**，而不是固定的。

### Step 3：前向计算

```python
h     = in_embed(center)          # (B, D)     v_c
u_pos = out_embed(context)        # (B, D)     u_o
u_neg = out_embed(neg)            # (B, K, D)  u_{w_k}

pos_score = (h * u_pos).sum(-1)                  # (B,)
neg_score = bmm(u_neg, h.unsqueeze(2)).squeeze(2)  # (B, K)

loss = -(logsigmoid(pos_score) + logsigmoid(-neg_score).sum(-1)).mean()
```

### Step 4：反向传播 & 更新

只有 **batch 里出现过的行**有梯度：
- `in_embed`：B 个中心词
- `out_embed`：B 个正样本 + B·K 个负样本

所以用 `sparse=True` + `SparseAdam`，只更新这些行。

### 用"吃 苹果"走一遍上面的流程（单个样本，K=5）

| 步骤 | 发生了什么 |
|---|---|
| 准备两套"账本" | `in_embed`：词作为**中心词**时查它；`out_embed`：词作为**上下文词或负样本**时查它。各 10 万行，每行一个 100 维向量 |
| 取正样本 | 滑动窗口框到"吃 苹果"：从 `in_embed` 取 $v_{吃}$，从 `out_embed` 取 $u_{苹果}$ |
| 采负样本 | 在噪声表的 1000 万个格子里随机抓 5 个，比如"石头、美丽、打篮球、今天、的"，从 `out_embed` 取它们的向量 |
| 打分（点积） | $s_+ = v_{吃}\cdot u_{苹果}$；$s_1 = v_{吃}\cdot u_{石头}$，…，一共 5 个负分数 |
| 算 loss | 正样本项 $-\log\sigma(s_+)$：$s_+$ 越大越接近 0；负样本项 $-\log\sigma(-s_k)$：$s_k$ 越小越接近 0。6 项加起来就是 loss |
| 反向更新 | 只改 **7 个向量**：`in_embed` 里的"吃"，以及 `out_embed` 里的"苹果"和 5 个假词。全 softmax 则要改 `out_embed` 的全部 10 万行 |

### CBOW 的区别

仅仅是 $h$ 的来源不同：把上下文 2W 个词的 `in_embed` 取平均（忽略 padding）作为 $h$，去预测中心词；负采样部分完全一样。

## 3. 为什么要用负采样

### (1) 计算量：从 O(|V|) 降到 O(K)

全 softmax 的分母要对整个词表求和。text8 词表约 7 万，真实语料常常百万级：

| 方法 | 每个样本要算的点积数 | 要更新的输出向量数 |
|---|---|---|
| Full softmax | \|V\| ≈ 70,000 | \|V\| (全部) |
| Hierarchical softmax | log₂\|V\| ≈ 17 | ~17 |
| **负采样 (K=5)** | **K+1 = 6** | **6** |

提速几个数量级，而且梯度是稀疏的——这才让在几十亿词上训练成为可能。

### (2) 效果并不差，甚至更好

论文实验里，负采样在词类比任务上对高频词的表现优于层次 softmax。原因之一是它的目标更"直接"：只要求区分真实搭配和噪声，这正是学语义相似度所需要的。

### (3) 实现简单

相比层次 softmax 要构建 Huffman 树、按路径计算，负采样就是几个 embedding 查表 + 点积 + logsigmoid，天然适合 GPU 批量计算。

### (4) 理论上的解释

Levy & Goldberg (2014) 证明：SGNS (Skip-gram + 负采样) 在最优点隐式地分解了一个矩阵：

$$
u_o^\top v_c = \text{PMI}(c, o) - \log K
$$

也就是说它在学"点互信息"——两个词共现比随机共现高多少。这也解释了为什么负采样学出的向量有很好的语义性质。

## 4. 工程师必须掌握的细节

### 4.1 为什么是 0.75 次方

- power = 1 (按词频采样)：负样本几乎全是 "the"、"of"，模型学不到什么
- power = 0 (均匀采样)：负样本全是罕见词，太容易区分，也学不到东西
- **0.75** 是折中：压低高频词、抬高低频词。纯粹是经验值，但几乎所有实现都沿用。

例：词频 0.9 vs 0.09 → 0.75 次方后变成 0.92 vs 0.16，比例从 10:1 缩小到约 5.7:1。

**常见疑问：为什么噪声表里高频词反而占的格子多？**

0.75 次方的作用**不是让低频词比高频词多**，而是**缩小两者的差距（劫富济贫）**，高频词仍然占多数。原因如下：

- **高频词必须多**：真实句子里"吃"旁边经常出现"的"、"了"。要让模型知道"吃+的"这种搭配没有语义价值，就得经常把"的"当负样本拿来"惩罚"。如果均匀抽（0 次方），抽到的几乎全是"饕餮"、"貔貅"这类生僻词，模型会学会偷懒：**"见到生僻词就打低分，见到常见词就打高分"**，却学不到真正的语义。
- **但也不能多得太离谱**：完全按词频（1 次方）建表，低频词几乎永远抽不到，它们在 `out_embed` 里的向量得不到训练。

用具体数字看一下：

| 词 | 出现次数 | 按词频 (1 次方) | 按 0.75 次方 |
|---|---|---|---|
| 的 | 10,000 | 10,000 | 10000^0.75 = **1000** |
| 苹果 | 100 | 100 | 100^0.75 ≈ **31.6** |
| 比例 | | 100 : 1 | **≈ 31.6 : 1** |

"的"依然是负样本的主力（1000 > 31.6），而"苹果"被抽中的机会从 1/100 提高到约 1/31。

### 4.2 K 怎么选

- 小语料：5~20
- 大语料：2~5（数据够多，每个正样本不需要那么多负样本）
- K 越大越慢，收益递减。本项目默认 5。

### 4.3 噪声表 (unigram table) 的技巧

- 用 `torch.multinomial` 每步采样在大词表上很慢；预先展开成 1e7 长度的表，采样只需 `randint`，这是 C 版 word2vec 的原始做法。
- 注意 `max(1, round(...))`：保证极低频词至少出现一次，否则它永远不会被采为负样本。
- 表要放在和训练同一个 device 上，避免每步 CPU↔GPU 拷贝。

### 4.4 负样本撞上正样本怎么办

采到的负样本可能恰好等于正样本（或中心词本身）。原版 C 代码只跳过了 `== target` 的情况；本项目不处理。词表大时概率极低，影响可以忽略。**但如果你的词表很小（比如推荐系统里几百个 item），必须处理**，否则会出现同一个词同时被推近和推远的矛盾梯度。

### 4.5 数值稳定性

用 `F.logsigmoid(x)`，**不要**写 `torch.log(torch.sigmoid(x))`：当 x 很负时 sigmoid 下溢为 0，log(0) = -inf，直接 NaN。

### 4.6 两套 embedding & 初始化

- `in_embed` 和 `out_embed` 必须是两套参数。若共享，一个词和自己的点积 $\|v\|^2$ 总是很大，而一个词几乎不会出现在自己的上下文里，会产生冲突。
- 初始化：`in_embed` 小均匀分布 `U(-0.5/D, 0.5/D)`，`out_embed` 全 0（和原版一致）。**两边不能同时为 0**，否则梯度恒为 0，永远学不动。
- 训练后通常只用 `in_embed`；也有人用 `in + out` 的平均，有时效果略好。

### 4.7 稀疏梯度

- `nn.Embedding(sparse=True)` 只能配 `SGD`、`SparseAdam`、`Adagrad`，**普通 Adam 会报错**。
- 不开 sparse 的话，每步会对整个 |V|×D 矩阵做优化器更新（Adam 的动量也是全量的），大词表下极慢且占显存。
- 不能随便加 weight decay：它会作用到所有行，破坏稀疏性。

### 4.8 负采样 vs 下采样，别搞混

| | 下采样 (subsampling) | 负采样 (negative sampling) |
|---|---|---|
| 作用对象 | 输入语料 | 损失函数 |
| 做什么 | 按概率**丢掉**高频词 | 随机抽词当**反例** |
| 目的 | 加速 + 提升低频词质量 | 避免全 softmax |

两者都针对高频词，但完全是两件事，经常配合使用。

### 4.9 Loss 的正常范围

初始时 `out_embed = 0`，所有分数为 0，loss = (K+1)·log2 ≈ 4.16 (K=5)。训练后一般降到 2 左右。如果：
- loss 一直是 4.16 → 梯度没传过去（检查初始化/优化器）
- loss 变成 NaN → 检查是否用了 `log(sigmoid)`、学习率是否过大

### 4.10 这个思想远不止 Word2Vec

负采样本质是**对比学习**：推近正样本、推远负样本。它的变体到处都是：
- 推荐系统的 item2vec、双塔召回（in-batch negatives、hard negatives）
- 对比学习 InfoNCE / CLIP / SimCLR：本质是"把负样本放进 softmax 分母"
- 知识图谱嵌入 (TransE)、图嵌入 (DeepWalk、node2vec)

在这些场景中，**负样本怎么采**（随机 / batch 内 / 困难负样本 / 流行度校正）往往比模型结构更影响效果，这是面试和实际工作中的高频考点。
